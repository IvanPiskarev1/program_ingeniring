# АСУИ сервисного центра

Несложное локальное веб-приложение на **Python + Django 5.2 LTS + SQLite** по лабораторным работам: приём изделия → диагностика → ремонт → контроль качества → выдача. HTML формирует Django; отдельная сборка frontend не нужна.

## Быстрый запуск в Windows (cmd)

cd C:\Prolog\9-10\app\service_center
.venv\Scripts\python.exe lan.py


.venv\Scripts\python.exe manage.py send_notifications --watch --ask-password 

Из папки `service_center`:

```bat
.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000
```

Откройте адрес, напечатанный сервером. Если порт занят или заблокирован Windows, можно запустить `.venv\Scripts\python.exe preview.py` — ОС выберет свободный порт, точный адрес появится в консоли. Оба сервера — только для разработки и локальной демонстрации.

Для установки на другом компьютере (Python 3.10–3.14; рекомендуется актуальный патч 3.12/3.13):

```bat
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
.venv\Scripts\python.exe manage.py migrate
.venv\Scripts\python.exe manage.py setup_roles
.venv\Scripts\python.exe manage.py seed_demo
.venv\Scripts\python.exe manage.py runserver
```

`requirements.lock.txt` фиксирует реально установленные версии; `requirements.txt` задаёт совместимые диапазоны. Здесь проект установлен на Python 3.11.0 — для реальной эксплуатации обновите Python до исправленного поддерживаемого выпуска.

## Вход

Команда `seed_demo` создаёт **пять обычных демо-учётных записей** с разными ролями. Случайные пароли находятся только в локальном файле **`demo-access.txt`** рядом с `manage.py`. Они не выводятся командой в консоль и не включаются в Git. Файл содержит чувствительные данные — не отправляйте его вместе с проектом.

| Логин | Роль | Основные действия |
|---|---|---|
| `demo_reception` | Приём | Новый заказ, клиенты, учебная оплата, выдача |
| `demo_master` | Мастер | Только назначенные заказы, диагностика, работы, детали |
| `demo_quality` | Контроль качества | Проверка очереди контроля, возврат на доработку |
| `demo_manager` | Руководитель | Все заказы, назначение мастера, загрузка, отчёты |
| `demo_admin` | Администратор | Все заказы для просмотра; сотрудники и справочники через `/admin/` |

Руководитель **не суперпользователь**, администратор не может назначить себе права суперпользователя или редактировать статусы вручную. Полный служебный доступ создаётся отдельно:

```bat
.venv\Scripts\python.exe manage.py createsuperuser
```

Сотрудникам в группе «Администратор» для доступа к Django Admin дополнительно нужен флаг «Статус персонала» (`is_staff`). Отключение сотрудника — снять «Активный», не удалять историю. Не используйте демо-пользователей для реальных персональных данных.

## Что реализовано

- Главная, вход и POST-выход, рабочий обзор и ролевые действия.
- Поиск заказов по номеру, клиенту, телефону, модели, серийному номеру; фильтры статуса, мастера, дат и пагинация.
- Приём нового или ранее зарегистрированного клиента/изделия; повторные обращения сохраняют общую историю изделия.
- Пять групп с серверными и объектными проверками прав; мастер не открывает чужие карточки и API.
- Назначение активного мастера руководителем, диагностика с категорией, оценкой и сроком.
- Работы, трудозатраты, детали; итог = работы + количество × цена. Оценка не прибавляется повторно.
- Контроль с положительным заключением или возвратом на доработку; после возврата нужна новая работа и новая проверка.
- Учебные частичные оплаты без переплаты; выдача только после контроля и полного расчёта, бесплатная выдача — с причиной.
- Транзакционные изменения с номером версии заказа; повтор старого действия отклоняется без дублирования. У приёма отдельный уникальный ключ отправки.
- Заказ-наряд с QR и печатным стилем. Клиент видит статус по секретной ссылке либо номеру **и** длинному секретному коду.
- Клиентский статус и история обновляются раз в 45 секунд; неуспешное обновление не стирает последние данные.
- Журнал почтовых уведомлений с очередью отправки через SMTP, аудитом назначений, операций и этапов.
- Загрузка мастеров; отчёт за период: приём, выдача, полный цикл, время в ремонте с доработкой, категории неисправностей, учебные оплаты отдельно от реальной выручки; CSV/XLSX с защитой от формул.
- SQLite, миграции, безопасное резервирование, тесты, адаптивная светлая/тёмная тема.

## Основные адреса

| Адрес | Назначение |
|---|---|
| `/` | Главная |
| `/accounts/login/` | Вход сотрудника |
| `/dashboard/` | Обзор |
| `/orders/`, `/orders/new/`, `/orders/<id>/` | Заказы, приём, карточка |
| `/orders/<id>/action/<action>/` | Форма операции; изменения только POST + CSRF |
| `/clients/`, `/clients/<id>/`, `/devices/<id>/` | Клиенты и история изделий |
| `/masters/` | Загрузка |
| `/reports/?start=2026-11-01&end=2026-11-30` | Отчёт; `&format=csv` или `xlsx` — выгрузка |
| `/track/`, `/track/<token>/` | Клиентская проверка |
| `/api/orders/`, `/api/orders/<id>/` | Авторизованный JSON, те же права и фильтры |
| `/api/public/status/<token>/` | Минимальный публичный JSON |
| `/orders/<id>/print/`, `/orders/<id>/qr/` | Документ и PNG QR (только сотрудникам) |
| `/admin/` | Сотрудники, справочники и неизменяемая история |

API использует сессионную авторизацию; свободной регистрации сотрудников нет. Недоступный мастеру объект — 404; неподходящая роль — 403; устаревшая операция — 409; ошибки полей остаются на форме. JSON не содержит токена или контактов клиента. Публичные страницы и JSON не кэшируются. Referrer-Policy — same-origin: внешним сайтам секретная ссылка не передаётся, внутри сайта сохраняется происхождение запросов для CSRF.

## Сценарий демонстрации

Все стартовые клиенты имеют префикс «Демо», телефоны `+7 (000) 000-00-00`, адреса `example.invalid`; суммы и результаты — учебные. Созданы шесть заказов на разных этапах. Это не настоящие клиенты, ремонты или статистика.

1. Приём: создать заказ, выбрать новый или существующий клиент и изделие.
2. Руководитель: открыть заказ и назначить `demo_master`.
3. Мастер: начать диагностику, записать результат, категорию, оценку и дату; перейти в ремонт.
4. Мастер: добавить работу и при необходимости детали, передать на контроль.
5. Контролёр: вернуть с комментарием; мастер добавляет доработку и повторно передаёт.
6. Контролёр: допустить к выдаче. Приём: записать учебную оплату и выдать.
7. Открыть клиентскую ссылку, печать; руководитель — отчёт и XLSX.
8. Новый заказ на прежнее изделие показывает историю обращений.

## Почтовые уведомления (Gmail SMTP)

При каждой смене статуса заказа создаётся запись очереди. Письмо уходит только клиенту с адресом почты и отметкой согласия; без них запись остаётся со статусом «Не отправляется». Отправку выполняет отдельная команда, ошибка почты не отменяет изменение заказа. Повторный запуск не рассылает письмо дважды; для ошибок максимум три попытки с паузой. Принятие письма почтовым сервером не подтверждает доставку клиенту.

Настройки заданы в `config/settings.py`: сервер `smtp.gmail.com`, порт 587, TLS, отправитель `service.center.asui@gmail.com` с именем «АСУИ Сервисный центр». Пароль приложения не хранится в коде: задайте переменную окружения `ASUI_EMAIL_PASSWORD` или вводите его скрыто командой. Обычный пароль Gmail не подходит - нужен пароль приложения, созданный в аккаунте Google (двухэтапная аутентификация → пароли приложений).

Проверочное письмо уходит только на разрешённый адрес `vapi64255899@gmail.com`:

```bat
.venv\Scripts\python.exe manage.py test_email --ask-password
```

Отправка очереди уведомлений (однократно или в режиме наблюдения каждые 15 секунд):

```bat
.venv\Scripts\python.exe manage.py send_notifications --ask-password
.venv\Scripts\python.exe manage.py send_notifications --watch --ask-password
```

Состояния в карточке заказа: «Ожидает отправки», «Передаётся серверу», «Передано почтовым сервером», «Не отправляется», «Ошибка отправки», «Результат неизвестен». Записи со статусом «Старая запись» - журнал до подключения почты, они не рассылаются. Для постоянной работы запустите `send_notifications --watch` на время смены статусов или настройте Планировщик заданий Windows; пароль в командной строке не указывайте.

```bat
.venv\Scripts\python.exe manage.py backup_database
```

`backup_database` использует SQLite Backup API (не копирование открытого файла), проверяет `PRAGMA integrity_check`, создаёт `backups/asui-*.sqlite3`. Удаляет только собственные копии старше 30 дней. При необходимости `--output ПУТЬ`. Для ежедневного запуска настройте Планировщик заданий Windows с абсолютными путями. Планировщик автоматически не создавался. Храните дополнительные копии отдельно от компьютера с ограниченным доступом.

Восстановление сначала **в отдельную папку**, не поверх работающей БД: выберите копию, задайте `ASUI_DB` путём к отдельному файлу и запустите проверки/сервер с этим окружением. Перед заменой основной БД остановите сервер и сохраните её. Тест проверяет резервирование и чтение восстановленной отдельной базы.

## Структура

`config/` — настройки и точки входа; `repairs/models.py` — данные; `forms.py` — ввод; `permissions.py` — роли и доступ к заказам; `services/orders.py` — транзакционные правила; `views.py` — рабочие страницы; `public.py` — QR и клиентский/API-доступ; `services/reports.py` и `report_views.py` — вычисление и выгрузка; `management/commands/` — служебные команды; `templates/`, `static/` — интерфейс; `repairs/tests/` — тесты.

## Ограничения и конфигурация

Это согласованная **локальная учебная версия**, а не производственная система, полностью выполняющая интеграционное и нагрузочное ТЗ лабораторных работ.

- Нет настоящей кассы, фискальных чеков, банковского списания, SMS/push, интернет-эквайринга и склада. Почтовые уведомления отправляются через SMTP Gmail; принятие письма сервером не подтверждает доставку.
- Один сервисный центр; нет статусов отказа, ожидания деталей и гарантийного спора. Не добавлялись неоговорённые бизнес-процессы.
- Проверка входа/подбора кода ограничена локальным кэшем. Для нескольких процессов требуется общий кэш или ограничение на reverse proxy.
- SQLite и локальные проверки не подтверждают 30 сотрудников/500 клиентов, доступность 99 %, требования 152-ФЗ или срок восстановления 4 часа.
- Настоящая эксплуатация требует HTTPS, производственного WSGI/ASGI-сервера, PostgreSQL по нагрузке, обновлённого Python, мониторинга, организационных мер и интеграций.
- Настройки по умолчанию: `ru-ru`, `Europe/Moscow`, `DEBUG=1`, доступ только localhost. Не открывайте `runserver` в Интернет.
- `DJANGO_DEBUG=0` требует `DJANGO_SECRET_KEY`; задайте также `DJANGO_ALLOWED_HOSTS`. В production включены HTTPS redirect и secure cookies.
- Секрет локального Django генерируется в `.local-secret`, не в исходниках. `.env`, БД, копии, окружение и `demo-access.txt` исключены из Git. Не публикуйте весь каталог архивом без проверки.
- Для QR и доступа с телефона используйте отдельный запуск ниже; `preview.py` остаётся только локальным.

## Запуск для телефона в доверенной сети Windows

Компьютер и телефон должны быть в одной сети: можно включить защищённую паролем Wi-Fi-точку доступа телефона и подключить к ней ноутбук; отдельный роутер не нужен. Подключение Windows должно иметь профиль «Частная». По умолчанию скрипт не меняет категорию сети и не открывает роутер в Интернет.

Если появилась ошибка «Кандидаты: нет», сначала посмотрите подключения (команда ничего не меняет):

```bat
.venv\Scripts\python.exe lan.py --list
```

Windows часто присваивает новой сети телефона профиль Public. Найдите IP ноутбука именно в сети телефона. Если одновременно подключены Ethernet/VPN, отключите их на время показа, чтобы не выбрать другой адрес. Для своей защищённой точки доступа выполните **в терминале администратора**, заменив `АДРЕС` найденным IP:

```bat
.venv\Scripts\python.exe lan.py --ip АДРЕС --trust-network --configure-firewall
```

`--trust-network` меняет только явно выбранное физическое подключение с Public на Private; не применяйте его в чужом или публичном Wi-Fi. Изменение профиля разрешает обнаружение/доступ по правилам частной сети Windows и сохраняется после остановки. После показа при необходимости верните профиль «Общедоступная» в параметрах Windows. Повторный запуск: `lan.py --ip АДРЕС`. `--list` и `--inspect` ничего не меняют. Если IP изменился, выберите новый IP и настройте правило заново. Доступ с самого телефона зависит также от ограничений его точки доступа.

Из папки `service_center`:

```bat
.venv\Scripts\python.exe lan.py
```

`lan.py` выбирает частный IPv4 с шлюзом, слушает только этот адрес, автоматически задаёт `ASUI_PUBLIC_URL` и `DJANGO_ALLOWED_HOSTS` в своём процессе. При нескольких подходящих адаптерах нужно явно указать адрес:

```bat
.venv\Scripts\python.exe lan.py --ip 192.168.0.101 --port 8080
```

Фактический адрес печатается в консоли. Откройте его на компьютере, войдите и заново откройте QR в карточке/печатном заказ-наряде. Старые распечатанные QR с localhost не изменятся. Сканируйте новый QR телефоном. Ввод переменных окружения вручную не нужен; обычный локальный запуск не изменён.

Для создания правила брандмауэра запустите следующую команду **в терминале от имени администратора**, из той же папки:

```bat
.venv\Scripts\python.exe lan.py --ip 192.168.0.101 --port 8080 --configure-firewall
```

Правило разрешает только TCP выбранного порта, адреса, сетевого адаптера и Python этого проекта; только профиль Private и источники LocalSubnet. При отказе в правах скрипт сообщает об этом, не отключает брандмауэр. Существующее правило не перезаписывается. Используйте обычную команду без `--configure-firewall` при следующих запусках. Порт 8080 должен быть свободен: остановите прежний сервер Ctrl+C перед повторным запуском. Для другого порта требуется своё правило.

Остановка сервера: Ctrl+C. Правило сохраняется для следующих запусков; удалить его можно в «Брандмауэр Защитника Windows в режиме повышенной безопасности», входящие правила, имя `ASUI-LAN-192.168.0.101-8080`.

При изменении IP после переподключения используйте новый адрес, создайте соответствующее правило и обновите QR/распечатки. Проверить выбор сети без запуска: `.venv\Scripts\python.exe lan.py --inspect`.

Это HTTP без шифрования и сервер разработки с DEBUG=1: только доверенная локальная сеть, не Интернет и не публичный Wi-Fi. Не настраивайте переадресацию порта на роутере. HTTPS/производственный сервер этим запуском не заменяются. Изоляция клиентов Wi-Fi и сторонние защитные программы могут блокировать телефон даже при корректном правиле Windows.

Отчёты DOCX и исходный план находятся в родительской папке и приложением не изменяются.

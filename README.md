# АСУИ сервисного центра

Python 3.11, Django 5.2 LTS, SQLite. Страницы формирует Django, отдельная сборка интерфейса не нужна.

## Запуск сайта и почты

Для обычного запуска на Windows откройте терминал и выполните две отдельные команды:

```bat
cd C:\Prolog\9-10\app\service_center
.venv\Scripts\python.exe lan.py
```

Откройте адрес, который напечатан в терминале. Компьютер и телефон должны находиться в одной доверенной частной сети. Если сеть не выбрана автоматически, смотрите раздел «Телефон в доверенной локальной сети».

Перед первым совместным запуском сохраните копию `.env.example` под именем `.env` рядом с `lan.py` и впишите пароль приложения Google в `ASUI_EMAIL_PASSWORD=`. Подробнее - в разделе «Почта». При наличии пароля вместе с сайтом запускается отправщик писем; отдельная команда и второе окно не нужны. Без пароля сайт запускается, но письма остаются в очереди.

Остановка сайта и отправщика - Ctrl+C в этом терминале. Не запускайте второй отправщик параллельно. После изменения кода или `.env` остановите сайт и запустите заново: `lan.py` не перечитывает их автоматически. Для обновления статических файлов в браузере используйте Ctrl+F5.

### Установка на другом компьютере

В установленном Python 3.11 из папки `service_center`:

```bat
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
.venv\Scripts\python.exe manage.py migrate
.venv\Scripts\python.exe manage.py setup_roles
```

Сотрудников создавайте через администратора. Существующие учётные записи при обновлении не меняются. Не переносите пароль приложения в исходный код или общие архивы.

### Обновление существующей базы и справочников

Остановите сайт и отправщик. Перед миграциями сохраните резервную копию:

```bat
.venv\Scripts\python.exe manage.py backup_database
.venv\Scripts\python.exe manage.py migrate
```

Для наполнения или дополнения справочников выполните по порядку:

```bat
.venv\Scripts\python.exe manage.py seed_parts_catalog
.venv\Scripts\python.exe manage.py seed_works_catalog
.venv\Scripts\python.exe manage.py seed_device_catalog
```

Это разовые операции при подготовке или обновлении данных, не обязательная часть каждого запуска. Затем запустите `lan.py`.

### Запуск только на компьютере

```bat
.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000
```

Откройте `http://127.0.0.1:8000/`. Этот вариант не запускает отправщик и не читает `.env`; отдельная команда почты приведена ниже.

## Приём устройства

- Поиск клиента по ФИО, телефону и почте: не менее двух символов, максимум десять результатов. Выбор заполняет редактируемые сведения и загружает изделия клиента.
- При выборе изделия заполняются тип, производитель, модель, серийный номер и комплектность последнего обращения этого клиента.
- «Новый клиент» снимает привязку и очищает поля. Телефоны сравниваются без пробелов и знаков; начальная 8 в российском номере равнозначна +7. При совпадении выберите существующего клиента.
- Без JavaScript используйте списки и кнопку «Загрузить выбранные данные». Сначала загрузите клиента, затем изделие. Эта кнопка не создаёт заказ.
- При сохранении изменения выбранного клиента и изделия записываются в общую карточку; комплектность сохраняется отдельно в новом заказе. Адреса в модели клиента нет.
- Принадлежность изделия проверяет сервер по истории заказов. Серийный номер производителя вводится вручную. Уникальный ключ формы защищает повторную отправку.

## Прайс-лист

`manage.py seed_device_catalog` дополняет единый справочник моделей из каталога деталей и уже принятых изделий. Команда сохраняет прежние данные и цены; повторный запуск не создаёт дублей. Перед первым запуском выполните `backup_database` и `migrate`.
В приёме разделены «Ранее принятое изделие» (только выбранного клиента) и «Модель из справочника» (все модели, без привязки к владельцу). Выбор модели заполняет тип, производителя и модель нового экземпляра; серийный номер вводится вручную. Без JavaScript работает кнопка загрузки модели. Для ручного изменения модели снимите выбор справочника.
В прайсе есть фильтр модели, связанные работы и детали; диагностика ищет позиции для точного совпадения типа, производителя и модели изделия. Неизвестная модель допускает общий поиск и ручной ввод. Связи являются рекомендациями подбора на уровне модели: перед установкой проверяйте ревизию и маркировку компонента. Для программных работ детали не требуются. Старые заказы не переписываются и не пересчитываются.

`/price/` содержит поиск по названию и артикулу, фильтры вида, категории и группы, страницы по 50 позиций. Приёмщик и мастер имеют доступ.
`seed_parts_catalog` добавляет 606 деталей: телефоны, ноутбуки и бытовая техника. Артикулы `AS-P-00001` и далее уникальны, генератор использует фиксированное зерно 20261125. Повторный запуск не меняет созданные позиции и не создаёт дублей. Существующие позиции сохраняются. Цены каталога - начальные значения, не котировки поставщиков; совместимость следует уточнять по модификации устройства перед установкой.
Единица измерения - штука; движения остатков нет.

В форме добавления детали мастер ищет по названию или артикулу, выбирает результат, задаёт количество и сохраняет. Возможен ручной ввод. Без JavaScript поиск возвращает до десяти кнопок добавления по одной штуке. Цена и название выбранной позиции проверяются сервером и копируются в заказ. Последующие изменения прайса не меняют прежние позиции заказа.

Диагностика (`/orders/<id>/diagnostics/`, также прежнее действие в карточке) содержит строки деталей и работ: тип, поиск, количество и цена. «Добавить позицию» создаёт строку, «Удалить строку» исключает её. Пустые строки не сохраняются. После выбора справочной позиции изменение названия или цены переводит строку в ручной ввод. При сохранённой привязке сервер повторно берёт название и цену из базы; ручные позиции не добавляются в справочник. Работы с количеством сохраняют общую стоимость позиции.

`manage.py seed_works_catalog` добавляет 24 работы по шести категориям неисправностей с фиксированным зерном 20261125, не меняет существующие записи. Перед миграцией выполните `manage.py backup_database`, затем `manage.py migrate` и `manage.py seed_works_catalog`.
Без JavaScript поиск под формой возвращает до десяти кнопок «Добавить» (количество 1). Добавление не сохраняет диагностику и не теряет введённые поля. Кнопка «Удалить строку» работает также без JavaScript, снимает справочную привязку вместе со строкой и сохраняет остальные введённые поля. Окончательное сохранение выполняется отдельной кнопкой и защищено версией заказа от повторной записи.

Работы в прайсе, диагностике и форме мастера берутся из единого `WorkCatalogItem`; старые строки `PriceItem(kind='work')` сохраняются в базе, но не используются для выбора. В формах работ и деталей доступен список с автоматическим заполнением названия и цены; без JavaScript используйте «Загрузить выбранную позицию». В диагностике список содержит позиции для модели устройства. При наличии строк первоначальная оценка вычисляется сервером из их суммы плюс диагностика; без строк остаётся ручная оценка. В браузере сумма обновляется при выборе, изменении количества, цены и удалении строк.

Итог = диагностика + стоимость работ + количество × цена деталей. Оценка ремонта повторно не прибавляется. Нулевая стоимость диагностики сохраняется как ноль. История сметы и ранее сохранённые согласования остаются в базе. Кнопка и окно «Согласование стоимости» удалены из интерфейса; прямой доступ к веб-форме закрыт.

Строки, сохранённые при диагностике, уже входят в заказ. Не добавляйте ту же работу или деталь повторно через форму мастера, если это не отдельная дополнительная позиция.

## Права и процесс

Приём - диагностика - ремонт - контроль качества - выдача. Группы: «Приём», «Мастер», «Контроль качества», «Руководитель», «Администратор». Мастер работает только с назначенными заказами. Изменения транзакционные, устаревшая версия даёт 409. Оплата частичная, переплата запрещена; выдача после контроля и полного расчёта. Печать выдачи доступна после регистрации выдачи.

API с сессионной авторизацией:
- `/api/clients/search/?q=`, `/api/clients/<id>/`, `/api/clients/<id>/devices/` - только право приёма, иначе 403; ответы не кэшируются и не содержат секретов клиентского доступа.
- `/api/parts/search/?q=`, `/api/works/search/?q=` - роли с доступом к прайсу, от двух символов, до десяти результатов; ответы не кэшируются. Поиск деталей по названию и артикулу, работ - по названию.
- `/api/device-models/` - все справочные модели без серийных номеров и сведений владельца, только право приёма, без кэша.
- `/api/parts/search/` и `/api/works/search/` принимают необязательный `model_id` для подбора по связям справочника моделей.
- `/api/orders/` - объектные ограничения как в списке заказов.
- `/api/public/status/<token>/` - минимальный статус без контактов и токена в JSON.

Изменения выполняются POST с CSRF. Экспорт отчётов: `/reports/?format=csv` или `xlsx`, ячейки защищены от инъекции формул.

## Почта

Gmail SMTP настроен в `config/settings.py`. Для совместного запуска сайта и отправщика сохраните копию `.env.example` как `.env` рядом с `lan.py` и заполните `ASUI_EMAIL_PASSWORD=` паролем приложения Google. Обычный пароль аккаунта не подходит. Пробелы между группами символов допустимы. `.env` уже исключён из Git; храните его только на своём компьютере, не пересылайте и не включайте в архивы проекта. Это открытый текст на диске, не зашифрованное хранилище.

```bat
cd C:\Prolog\9-10\app\service_center
.venv\Scripts\python.exe lan.py
```

`lan.py` загружает из `.env` только `ASUI_EMAIL_PASSWORD`; заданная переменная окружения имеет приоритет. Файл читается до настройки Django. При запуске сайта один отправщик проверяет очередь каждые 15 секунд, отдельное окно не требуется. Ctrl+C останавливает оба процесса. При остановке во время SMTP-обмена запись может остаться в состоянии отправки: перед повтором проверьте «Отправленные». Сбой отправщика показывается в терминале, автоматического перезапуска нет. Не запускайте параллельно прежний `send_notifications --watch`. Команды `--list` и `--inspect` почту не запускают. Без пароля сайт работает с предупреждением, письма остаются в очереди. После изменения `.env` перезапустите сайт.

Письма ставятся в очередь при смене статуса для клиентов с почтой и согласием. Запуск отправщика обрабатывает уже накопленные письма, а не только будущие. При неизвестном результате SMTP автоматического повтора нет. Проверочное письмо при необходимости: `manage.py test_email --ask-password`.

Прежний отдельный запуск сохранён для `runserver` и `preview.py` (они `.env` не читают):
```bat
.venv\Scripts\python.exe manage.py send_notifications --watch --ask-password
```

## Резервные копии

```bat
.venv\Scripts\python.exe manage.py backup_database
```

SQLite Backup API создаёт проверенную копию в `backups/`. Копии старше 30 дней удаляются командой по её собственному шаблону. Код и настройки в копию базы не входят. Расписание автоматически не создаётся. Храните дополнительную копию на отдельном носителе. Для проверки восстановления задавайте `ASUI_DB` путём к отдельной копии, не заменяйте открытую рабочую базу.

## Телефон в доверенной локальной сети

Подключите ноутбук к защищённой точке доступа телефона. `lan.py --list` показывает подключения. Для выбранного адреса: `.venv\Scripts\python.exe lan.py --ip АДРЕС`. При необходимости настройте только эту доверенную сеть из терминала администратора: `lan.py --ip АДРЕС --trust-network --configure-firewall`. Не отключайте брандмауэр. Скрипт задаёт `ASUI_PUBLIC_URL` и `DJANGO_ALLOWED_HOSTS` в своём процессе. Открывайте адрес из консоли, QR формируется с этим адресом. Сервер останавливается Ctrl+C. Не открывайте HTTP-сервер разработки в Интернет или публичную сеть.

## Проверки

```bat
.venv\Scripts\python.exe manage.py makemigrations --check --dry-run
.venv\Scripts\python.exe manage.py check
.venv\Scripts\python.exe manage.py test repairs
.venv\Scripts\python.exe manage.py smoke_check
```

Тесты используют отдельную базу. `smoke_check` выбирает существующего активного сотрудника каждой группы, проверяет страницы, экспорт и отдельную восстановленную копию базы; это не браузерная проверка.

## Структура

| Путь от папки `service_center` | Назначение |
| --- | --- |
| `lan.py`, `mail_launcher.py` | Запуск в доверенной сети, чтение пароля почты и управление отправщиком |
| `config/` | Настройки и маршрутизация |
| `repairs/models.py`, `repairs/migrations/` | Данные и схема базы |
| `repairs/forms.py`, `repairs/intake_data.py`, `repairs/catalog_api.py`, `repairs/views.py` | Формы, автозаполнение, API справочников и рабочие страницы |
| `repairs/diagnostics.py`, `repairs/diagnostic_items.py` | Строки диагностики и их проверка |
| `repairs/permissions.py`, `repairs/services/orders.py` | Права и транзакционные правила |
| `repairs/public.py`, `repairs/report_views.py`, `repairs/services/reports.py` | Клиентский статус, печатные формы и отчёты |
| `repairs/management/commands/` | Наполнение каталогов, почта, резервирование и проверки |
| `templates/`, `static/` | Страницы, стили и обычный JavaScript |
| `repairs/tests/` | Проверки приложения |

Секреты, локальная база, резервные копии и файлы доступа не предназначены для публикации. Настройки сети и почты передаются окружением либо локальным скрытым вводом.
